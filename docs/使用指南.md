# 个人图片仓库使用指南

这套项目的工作流程是：

```text
拖拽图片 / 剪贴板截图
        ↓
PicGo（本机，持有你的 Token）
        ↓ GitHub API 上传
GitHub 公开仓库 / main / images/
        ↓
GitHub Raw 或 jsDelivr 图片链接 → 博客 / Markdown / 网页
```

没有需要部署的后端，也不需要开通 GitHub Pages。PicGo 直接向远程仓库上传，**每次上传不需要你在本地执行 git push**。

## 0. 先了解这套方案的边界

- 仓库需要设为 **Public**，图片和提交历史对所有人可见。只上传准备公开的图片；个人照片可先移除不希望公开的定位等元数据。
- **jsDelivr 的当前条款限制通用图片/媒体托管**，并明确列举图床网站。项目保留你需要的 jsDelivr 配置，但默认使用 GitHub 原始链接。若图片是某个公开项目或博客的资源，请按实际用途核实适用性，有疑问向服务方确认；不能假定“个人使用”自动不受限制。[jsDelivr 官方条款 §6](https://github.com/jsdelivr/jsdelivr/blob/master/Terms%20of%20Use.md)
- GitHub Raw 同样不是专门的图片存储产品。本方案用于少量公开图片，不承诺特定地区的速度或永久可用性；大量图片或高可用需求应另行选择专门的存储服务。
- 本项目将单张图片控制在 **小于 20,000,000 字节（20 MB）**，建议日常压缩到 1–5 MB；脚本检查扩展名和文件大小，不会自动压缩，也不会拦截 PicGo 本身的上传。jsDelivr 对 GitHub 单文件默认存在 20 MB 限制。[限制说明](https://github.com/jsdelivr/jsdelivr#restrictions)
- Token 相当于上传凭据，仅粘贴到 PicGo。不要写进 Git 命令、README、截图、公开配置或聊天中；`.gitignore` 也无法保护曾经提交过的凭据。

## 1. 创建 GitHub 仓库

打开 [GitHub 新建仓库](https://github.com/new)，按下面填写：

| 项目 | 建议值 |
| --- | --- |
| Owner | 你自己的 GitHub 账号 |
| Repository name | `ImageHosting-nobYoQ` |
| Description | 个人博客与项目图片资源 |
| Visibility | **Public** |
| Add a README file | **不要勾选**，本项目已经提供 |
| Add .gitignore / Choose a license | 暂不选择，避免生成另一套初始历史 |

点击 **Create repository**。记下地址 `https://github.com/你的用户名/ImageHosting-nobYoQ`。

如果你已经创建了带 README 的仓库，先不要照抄后面的首次推送步骤。可以把它克隆到一个新目录，再把本项目文件复制进去，保留该仓库的 `.git`，在那份副本中配置、提交和推送；不需要强制推送。

## 2. 生成专属配置

在 **PowerShell 7** 打开项目目录，运行：

```powershell
Set-Location -LiteralPath 'E:\Project\ImageHosting-nobYoQ'
$GitHubUser = '替换成你的GitHub用户名'
.\scripts\Initialize-ImageHosting.ps1 -Owner $GitHubUser
```

这里的用户名是 GitHub 个人主页地址中的账号名，不是显示名称或邮箱。以后如果重新打开 PowerShell，需要重新设置 `$GitHubUser`。

脚本会写入：

- `image-hosting.json`：仓库、分支、图片目录和链接类型，可提交到 GitHub。
- `.local/picgo-settings.md`：与你的仓库匹配的 PicGo 填写表。
- `.local/picgo.generated.json`：Token 为空的 PicGo 字段示例，仅用于参考。
- `images/`：默认存储目录；已有图片会保留。

`.local/` 已被 Git 忽略。脚本不会安装 PicGo、读取或写入 Token，也不会替换已有的 PicGo 配置。

如果要采用自定义仓库名或目录：

```powershell
.\scripts\Initialize-ImageHosting.ps1 -Owner $GitHubUser -Repo 'my-images' -Branch 'main' -ImagePath 'images/'
```

建议保持 `main` 和 `images/`。辅助脚本支持 `assets/images/` 等英文目录，分支名暂不支持斜杠。所有后续命令、PicGo 和 GitHub 必须使用同一仓库与分支；重新运行初始化脚本时，也应重新传入你自定义的参数。

### 按需启用 jsDelivr

核对第 0 节的服务限制后，用以下命令选择 jsDelivr 输出：

```powershell
.\scripts\Initialize-ImageHosting.ps1 -Owner $GitHubUser -Delivery jsdelivr
```

其完整图片地址形式是：

```text
https://cdn.jsdelivr.net/gh/你的用户名/ImageHosting-nobYoQ@main/images/文件名.png
```

切回 GitHub Raw 则使用 `-Delivery github`，并在 PicGo 中清空“自定义域名”。配置脚本不会自动修改 PicGo，已经粘贴到文章里的旧链接也不会自动变化。

## 3. 首次发布项目到 GitHub

需要安装 [Git for Windows](https://git-scm.com/downloads/win)；当前工作环境已检测到 Git，且本地目录已初始化为 `main`。下面的命令也适用于重新下载的无 Git 元数据副本。已有 `.git` 时跳过初始化，先确认当前分支及远程仓库与预期一致。

```powershell
if (-not (Test-Path -LiteralPath '.git')) {
    git init -b main
    if ($LASTEXITCODE -ne 0) { throw 'Git 初始化失败，请先处理错误。' }
}

git status --short
```

如果尚未设置 Git 作者信息，用**你自己的**名称和 GitHub 账号邮箱设置，仅作用于当前仓库：

```powershell
git config user.name '你的GitHub用户名'
if ($LASTEXITCODE -ne 0) { throw '设置提交作者失败。' }
git config user.email '你的GitHub提交邮箱'
if ($LASTEXITCODE -ne 0) { throw '设置提交邮箱失败。' }
```

邮箱可以使用 [GitHub 邮箱设置](https://github.com/settings/emails)中提供的隐私邮箱，勿照搬别人的 `noreply` 地址。

运行本地检查，并明确列出要加入版本控制的文件：

```powershell
.\scripts\Test-ImageHosting.ps1
# 上一条通过后再继续；未填写用户名时会提示先初始化配置。

git add -- .gitignore .gitattributes .editorconfig README.md image-hosting.json config docs scripts tests images
if ($LASTEXITCODE -ne 0) { throw '暂存失败，请先处理错误。' }
git diff --cached --stat
```

确认列表中没有 PicGo 的真实配置、Token 或 `.local/`，再提交和推送：

```powershell
git commit -m 'Initialize personal image hosting'
if ($LASTEXITCODE -ne 0) { throw '提交失败，请先处理错误。' }

$RemoteUrl = 'https://github.com/{0}/ImageHosting-nobYoQ.git' -f $GitHubUser
git remote add origin $RemoteUrl
if ($LASTEXITCODE -ne 0) { throw '设置 origin 失败；若已存在，请先核对，不要重复添加或强行覆盖。' }

git push -u origin main
if ($LASTEXITCODE -ne 0) { throw '推送失败，请根据 Git 的提示处理登录、网络或远程历史。' }
```

如果用了不同仓库名，请同步修改 `$RemoteUrl`。首次推送可能由 Git Credential Manager 打开浏览器要求你登录 GitHub，按界面完成登录；GitHub 账号密码不能当作 Git HTTPS 密码。PicGo 专用 Token 不需要写入远程地址。

推送成功后，在 GitHub 页面确认：分支为 `main`，能看到 `README.md` 和 `images/example.svg`。**新建的空仓库还没有 `main`，必须先完成这次初始化提交，再配置上传。**

## 4. 创建仅用于 PicGo 的 Token

打开 [Fine-grained personal access tokens](https://github.com/settings/personal-access-tokens)，选择 **Generate new token**：

| 项目 | 设置 |
| --- | --- |
| Token name | 例如 `PicGo-ImageHosting` |
| Expiration | 选择一个你便于维护的到期时间，例如 90 天 |
| Resource owner | 你自己的账号 |
| Repository access | **Only select repositories**，仅选择这个图床仓库 |
| Repository permissions → Contents | **Read and write** |
| Metadata | 保持自动提供的 Read-only |

其余权限不需要额外开启。生成后把 Token **直接粘贴到下一步 PicGo 的 Token 输入框**，不要填进本项目文件。到期后新建/轮换 Token，并更新 PicGo 即可。

这使用 GitHub 为内容上传 API 提供的最小仓库权限。[官方 Token 指南](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)、[Contents API 权限](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents)

旧教程可能要求创建具有整个 `repo` 权限的 classic Token；本指南优先使用仅授权一个仓库的 fine-grained Token。若当前客户端报鉴权错误，先更新官方 PicGo，并检查 Token 的仓库选择、Contents 权限、到期时间与分支规则。

## 5. 安装并配置 PicGo

从 [PicGo 官方 Releases](https://github.com/Molunerfinn/PicGo/releases/latest)下载适配 Windows 的稳定版安装程序并安装。内置 GitHub 图床即可，无需额外插件。

进入 **图床设置 → GitHub**，按照本项目生成的 `.local/picgo-settings.md` 填写。默认设置为：

| PicGo 字段 | 填写内容 |
| --- | --- |
| 设定仓库名 | `你的用户名/ImageHosting-nobYoQ`，不要填完整网页地址 |
| 设定分支名 | `main` |
| 设定 Token | 刚生成的 Token，仅填在 PicGo 内 |
| 指定存储路径 | `images/`，有末尾斜杠，没有开头斜杠 |
| 设定自定义域名 | 默认留空，使用 GitHub 原始链接 |

如果选择 jsDelivr，“自定义域名”填写：

```text
https://cdn.jsdelivr.net/gh/你的用户名/ImageHosting-nobYoQ@main
```

**这里不要加 `/images/`、文件名或末尾 `/`。** PicGo 会把“存储路径 + 文件名”接在自定义域名后面。

保存配置，选中这份配置并**设为默认图床**。在设置中开启“时间戳重命名”，在上传区选择 `Markdown` 或 `URL` 复制格式。

本项目的 JSON 是字段参考，**不是可以覆盖 PicGo 整个 `data.json` 的完整配置**。请优先在界面填入，避免丢失已有相册、插件和其他图床设置。PicGo 会自行在用户配置目录保存上传凭据；不要把该配置目录复制到仓库中。[PicGo 官方配置说明](https://picgo.github.io/PicGo-Doc/zh/guide/config.html)

## 6. 验证第一次上传

先检查已推送的示例图片：

```powershell
.\scripts\Get-ImageLink.ps1 -Path 'images/example.svg' -Format Url
.\scripts\Test-ImageHosting.ps1 -Online
```

`-Online` 会进行匿名只读请求，依次检查仓库、分支、Raw 图片；选择 jsDelivr 时也检查 CDN。不会检查 Token，也不会验证写入权限。普通模式只检查本地文件扩展名与大小，不验证图片解码或远程状态。

接着测试实际上传：

1. 准备一张小于 1 MB、可以公开的 PNG/JPG，拖入 PicGo 上传区。
2. 上传成功后，粘贴复制的链接到浏览器；如果复制的是 Markdown，取括号内的 URL 打开。
3. 在 GitHub 的 `main/images/` 中确认文件存在，并核对文件名。
4. 能在浏览器中看到刚上传的图片，才算完成上传与访问验证。

选择 jsDelivr 时，输出应类似：

```markdown
![示例](https://cdn.jsdelivr.net/gh/你的用户名/ImageHosting-nobYoQ@main/images/20261003123456789.png)
```

实际文件名由 PicGo 决定，以其上传结果为准。若自定义了图片目录，远程检查请传入实际存在的仓库路径：

```powershell
.\scripts\Test-ImageHosting.ps1 -Online -Path 'assets/images/实际文件名.png'
```

## 7. 日常使用

### 上传和引用

以后直接用 PicGo 拖拽上传、剪贴板上传，复制结果到文章即可。推荐时间戳命名，避免同名文件导致上传冲突、旧图片被引用或缓存不更新。更新一张图片时，给它新文件名，再替换文章链接。

辅助脚本可以为已经存在的远程文件生成链接，无需先把图片拉到本机：

```powershell
.\scripts\Get-ImageLink.ps1 -Path 'images/截图 01.png' -Format Markdown -Alt '操作截图'
.\scripts\Get-ImageLink.ps1 -Path 'images/截图 01.png' -Format JsDelivr
.\scripts\Get-ImageLink.ps1 -Path 'images/截图 01.png' -Format Raw
.\scripts\Get-ImageLink.ps1 -Path 'images/截图 01.png' | Format-List
```

参数是**从仓库根目录开始的未编码路径**，包括 `images/`，不要传 `E:\...` 或完整网址。脚本按路径段编码中文、空格、`#`、`%` 等字符，避免链接截断；不会重复添加 `images/`。生成链接不会上传文件，也不能证明远程文件存在。

### 本地同步与备份

PicGo 写入的是远程仓库，本地目录不会自动出现新图片。准备修改本项目或备份时，在本地没有待处理修改的情况下运行：

```powershell
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw '同步失败；请先提交本地修改或处理分支分叉，不要强制覆盖。' }
```

如果本地和远程都产生了提交，`--ff-only` 会停止。先查看历史和修改，按具体情况合并；不要通过 force push 覆盖 PicGo 已上传的图片。平时保留一份图片原文件备份。

### 缓存与删除

- `@main` 明确引用分支；jsDelivr 官方文档说明分支链接可能缓存约 12 小时。新上传文件或同名更新不应被视为一定即时生效。
- 更新内容优先使用新文件名。必要时可通过 [jsDelivr 官方缓存刷新工具](https://www.jsdelivr.com/tools/purge)提交完整 URL，实际刷新能力以工具结果为准。
- Commit/tag 链接具有更强的缓存不可变性，不适合希望同名替换内容的场景。[缓存文档](https://github.com/jsdelivr/jsdelivr#caching)
- PicGo 内置相册里的删除主要是清理本地记录，不等于删除 GitHub 文件。需要删除源文件时，在 GitHub 仓库中删除并提交。
- 删除源文件也不保证 CDN 缓存及 Git 历史中的副本立即消失。因此这不是可撤回的私密图片方案。[PicGo 相册说明](https://picgo.github.io/PicGo-Doc/zh/guide/config.html)、[jsDelivr 存储说明](https://github.com/jsdelivr/jsdelivr#github)

## 8. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 脚本提示未配置用户名 | 先运行 `Initialize-ImageHosting.ps1 -Owner '真实用户名'` |
| PowerShell 无法识别脚本特性 | 使用 PowerShell 7，在项目根目录执行；不要改用 Windows PowerShell 5.1 |
| PowerShell 执行策略阻止脚本 | 查看系统/组织的脚本策略，按允许的方式处理；也可手动填写 PicGo 配置完成上传，脚本是辅助工具 |
| 上传 401 | Token 无效、填错或过期，重新生成并更新 PicGo |
| 上传 403 / Resource not accessible | 检查 Token 是否选中正确仓库、Contents 是否读写、账号是否有写权限；也检查限流和要求 PR 的分支规则 |
| 上传 404 / 分支不存在 | 确认仓库名为 `用户名/仓库名`，且首次提交已推到 `main` |
| 同名上传 409 / 422 或拿到旧图 | 换新文件名并检查 GitHub 是否确实写入；不要仅凭相册记录判断更新成功 |
| PicGo 成功，GitHub 没有新文件 | 核对当前默认图床、选中的配置和分支，检查实际文件名和日志 |
| GitHub 有图片，jsDelivr 404 | 检查仓库是否公开、路径大小写、`@main` 和是否重复 `/images/`，再考虑缓存尚未更新 |
| 图片更新后还是旧内容 | 新文件名重新上传并更新引用；浏览器缓存与 CDN 缓存需分别考虑 |
| jsDelivr 403 / 超限 | 查看响应原因，检查单文件大小与用途限制；不要通过改仓库名或域名规避服务限制 |
| GitHub Raw 能打开，jsDelivr 超时 | 分别检查当前网络可达性；可切回 Raw 并更新文章链接，不能据此认定上传失败 |
| `git push` 被拒绝，提示 fetch first | PicGo 可能已产生远程提交；先同步并处理历史分叉，不要 force push |

不要分享包含 Token 的完整日志或 PicGo 配置。如果凭据曾泄露，先在 GitHub 撤销该 Token，再生成新凭据；只从文件中删除并不足以撤销访问。
